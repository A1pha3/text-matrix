### Anthropic 把 Messages API 迁到 Rust：每请求 CPU 降约 70%，首字延迟降约 20%

来源: Anthropic 官方博客
原文: [原文](https://www.anthropic.com/research/migrating-api-to-rust)
摘要: Anthropic 把 Messages API 从 Python 重写为 Rust，这个 API 是客户以及 Claude Code、Cowork 等自家应用访问 Claude 的主要通道，2024 年初到 2026 年秋流量增长约 1800 倍，Python 在对象创建、内存释放和任务交接上的开销已无法承受。难点不是写代码而是验证正确性——2024 年有工程师建议迁 Go 或 Rust 时被直接否掉，直到 2026 年 5 月 Claude 已能写出 Anthropic 合入代码的 80% 以上，重写才变得可行。做法是把线上的 Python 版 Messages API 本身当作验证器，在生产流量上比对两版差异，自动派发智能体修复，全程未停服、未冻结功能开发；此前只重写模型输出解析部分时 CPU 仅下降 8% 到 10%，最终整版迁移使每请求 CPU 用量下降约 70%、首字延迟中位数下降约 20%。文中提出的核心问题是生成者与验证者之间的落差：数独这类题验证远比求解容易，但 Claude 如今越来越多地接手"生成比验证更容易"的活计——在真实系统里用户依赖测试集覆盖不到的边界情况，很难写出涵盖一切的"正确"定义，把生产 API 变成验证器是绕开这个死结的办法。

摘要: 作者把 2015 年谷歌内部 go/codegolf 竞赛的 32 道题搬回今天，做成 32 题 × 8 种语言 = 256 格的基准，每模型每题限时 30 分钟，按字节数计分而非只看能否跑通，规则宽松到允许未定义行为、编译器怪癖、非标准库特性甚至硬编码测试用例。JS/PY/C++ 合并分上，GPT-6.2 Astra 拿到 92.265%，人类纪录为 87.533%，且在三种语言上分别高于人类，是目前唯一超过人类线的模型；96 格中模型赢了 62 格，但仍有 14 格人类的解法仍比所有模型更短。基准里有两个反直觉的观察：GPT-6 Sol 即使在最高推理强度下通常 5 到 10 分钟就停手，而所有 GPT-5 系列模型在大多数格子上仍会跑满 30 分钟，作者认为这解释了不少排名差距；而语言集合横跨命令式、Haskell 的函数式、Racket 的 Lisp 前缀记法和训练数据稀缺的栈式深奥语言 GolfScript，跨语言 golf 靠的不是重复熟悉模式。**"击败没人认真优化的参考答案"没有意义，击败花了整整一周比赛的真实纪录才是**——这正是这份基准想衡量的东西。
