# Hello 算法拆解：13 万 Star 的动画图解教程，动画是手工拆帧，一键运行全靠标准库

算法入门材料大多要在两头之间取舍：图多的往往讲得浅，代码全的往往读不动。Hello 算法（[krahets/hello-algo](https://github.com/krahets/hello-algo)）同时压住了两头，靠的不是什么技术方案，而是两条朴素的纪律——

**动画不用自动播放的 GIF**。每个算法过程被作者手工拆成一组连续静态帧，网页上以标签页呈现，读者可以停在任何一步对照文字，比盯着一段自动循环的 GIF 反复倒带高效得多。

**代码只用标准库**。每个示例文件自包含，不依赖构建工具和第三方包，复制就能跑；`pythontutor/` 目录还预生成了 Python Tutor 链接，能在浏览器里单步看执行。

这两条纪律单独看都不新奇，难得的是落进一份以中文写就、维护三年多的完整教程，并且从头到尾没有走样。截至 2026-10-03，仓库有 130,575 颗 Star、15,509 个 Fork，是 GitHub 上 Star 数最高的中文开源教程之一。

## 动画图解：手工拆帧，标签页呈现

"动画图解"是这个项目最出圈的标签，仓库里的真实实现却和多数人想象的不一样——**全库的真 GIF 只有 5 个，全部位于 `docs/index.assets/`，仅用于首页演示**。正文章节的动画是另一套做法。

以第 11 章冒泡排序为例，`docs/chapter_sorting/` 下有一个与正文同名配对的 `bubble_sort.assets/` 目录，里面是 8 张 1280×720 的 PNG：1 张总览图（`bubble_sort_overview.png`），加 7 张过程帧（`bubble_operation_step1.png` 到 `step7.png`）。正文先用一段文字讲清整体的冒泡过程，再用 MkDocs 的标签页语法把 7 张帧组织成 `<1>` 到 `<7>` 的步骤标签，读者点击标签逐步查看交换过程；需要看全局时切到总览图，图片点击后可放大（glightbox 插件）。

这种设计在两处细节上露出了"手工"的痕迹。其一，仓库根目录没有任何动画生成脚本，帧是作者用绘图工具逐张画出来的；其二，[贡献指南](https://www.hello-algo.com/chapter_appendix/contribution/)明确写着"图片无法直接修改，需要通过新建 Issue 描述问题，我们会尽快重新绘制并替换"——图是人画的，不是脚本渲的。

自动播放的 GIF 和可停留的分步帧，信息量相同，学习成本不同：GIF 要求读者在循环播放中抓拍那一瞬，分步帧允许读者停在与文字对齐的任意一步。对入门材料，后者是更贴合的选择，代价是作者画图的工作量。

## 一键运行：只用标准库的纪律

"一键运行"听起来像有个执行框架，实际靠的是代码自律。看仓库原码，`codes/python/chapter_sorting/bubble_sort.py`：

```python
def bubble_sort(nums: list[int]):
    """冒泡排序"""
    n = len(nums)
    # 外循环：未排序区间为 [0, i]
    for i in range(n - 1, 0, -1):
        # 内循环：将未排序区间 [0, i] 中的最大元素交换至该区间的最右端
        for j in range(i):
            if nums[j] > nums[j + 1]:
                # 交换 nums[j] 与 nums[j + 1]
                nums[j], nums[j + 1] = nums[j + 1], nums[j]


def bubble_sort_with_flag(nums: list[int]):
    """冒泡排序（标志优化）"""
    n = len(nums)
    # 外循环：未排序区间为 [0, i]
    for i in range(n - 1, 0, -1):
        flag = False  # 初始化标志位
        # 内循环：将未排序区间 [0, i] 中的最大元素交换至该区间的最右端
        for j in range(i):
            if nums[j] > nums[j + 1]:
                # 交换 nums[j] 与 nums[j + 1]
                nums[j], nums[j + 1] = nums[j + 1], nums[j]
                flag = True  # 记录交换元素
        if not flag:
            break  # 此轮"冒泡"未交换任何元素，直接跳出


"""Driver Code"""
if __name__ == "__main__":
    nums = [4, 1, 3, 1, 5, 2]
    bubble_sort(nums)
    print("冒泡排序完成后 nums =", nums)

    nums1 = [4, 1, 3, 1, 5, 2]
    bubble_sort_with_flag(nums1)
    print("冒泡排序完成后 nums =", nums1)
```

三个特征值得注意：只依赖标准库，无第三方包；文件自带 Driver Code（`if __name__ == "__main__"` 测试入口），单文件直接 `python bubble_sort.py` 出结果；函数签名和注释与正文严格一致，读者在"读文"与"跑码"之间切换不需要翻译。Java 版同理——文件头带 `package chapter_sorting;` 声明，`import java.util.*`，用 `javac` 直接编译，不需要 Maven 或 Gradle。

`codes/` 目录按语言分子目录，目前 14 种：C、C++、C#、Dart、Go、Java、JavaScript、Kotlin、Python、Ruby、Rust、Swift、TypeScript、Zig。每个语言子目录的章节命名与文档镜像对应。顺带一提，README 里写的"已支持 12 门编程语言"是旧文案，以 `codes/` 目录实际数到的 14 个为准（README 的 badge 区也只列了 13 个，Zig 没有徽章但代码在）。

不想在本地配 14 套语言环境的读者，仓库准备了一个备选项：`codes/docker-compose.yml` 构建一个名为 `hello-algo-code` 的交互式容器，通过 `LANGS` 参数按需安装语言环境（内置了 Python 3.10、g++、OpenJDK 17、.NET SDK 8.0 的安装流程），起容器后在里面跑各语言示例。

### Python Tutor 集成

比"跑出结果"更进一步的是看清执行过程。`codes/pythontutor/` 目录按章节存放预生成的 [pythontutor.com](https://pythontutor.com/) 链接——每个链接把完整源码 URL 编码后指向 Python Tutor 的渲染页面，按函数粒度拆分（比如冒泡排序的基本版和标志优化版各一条）。网页版正文的代码块下方有"可视化运行"按钮，点击即在浏览器里单步查看变量、堆栈与引用关系的变化。这条路径不需要装任何东西，是全项目门槛最低的执行入口。

## 章节结构：16 章就是一条学习路径

`docs/` 目录按章节组织，`mkdocs.yml` 的导航顺序即官方推荐的学习顺序：

| 阶段 | 章节 |
|------|------|
| 开篇 | 序（`chapter_hello_algo`，作者自述创作缘起）→ 第 0 章前言（`chapter_preface`，含"如何使用本书"） |
| 入门 | 第 1 章初识算法 → 第 2 章复杂度分析 → 第 3 章数据结构 |
| 基础数据结构 | 第 4 章数组与链表 → 第 5 章栈与队列 → 第 6 章哈希表 |
| 进阶数据结构 | 第 7 章树 → 第 8 章堆 → 第 9 章图 |
| 基础算法 | 第 10 章搜索 → 第 11 章排序 → 第 12 章分治 |
| 高级算法 | 第 13 章回溯 → 第 14 章动态规划 → 第 15 章贪心 |
| 收尾 | 第 16 章附录（编程环境安装、一起参与创作、术语表）→ 参考文献 → 纸质书 |

每章的收尾是固定的"小结 + 练习"两件套（`summary.md` + `exercises.md`），练习是手算模拟和概念辨析——比如给定数组模拟排序的每一轮、比较两种排序对相等元素的处理——附可折叠的参考答案，不是 LeetCode 风格的在线判题。节标题带 `*` 的是选读内容（如"3.3 数字编码 *"、"4.4 内存与缓存 *"），赶时间的读者可以跳过。

关于阅读顺序，官方没有给出"初学者路径 / 面试路径"之类的分叉，`chapter_preface/suggestions.md` 给的是一条三阶段路线：

1. **阶段一：算法入门**——熟悉数据结构的特点与用法，理解算法的原理、流程与效率，这部分正是本书覆盖的内容；
2. **阶段二：刷算法题**——从热门题开刷，先积累至少 100 题，按艾宾浩斯遗忘曲线复习 3～5 轮，题单见作者维护的 [LeetCode-Book](https://github.com/krahets/LeetCode-Book)；
3. **阶段三：搭建知识体系**——读算法专栏、解题框架与教材，刷题转向按专题分类、一题多解。

这个定位写得诚实：本书只负责阶段一，不假装替你完成刷题。

## 一个读者的完整学习路径

把上述机制串一遍。假设你要用这本书学懂冒泡排序：

1. 打开 [第 11 章冒泡排序](https://www.hello-algo.com/chapter_sorting/bubble_sort/)，先看总览图建立整体流程印象；
2. 点 `<1>` 到 `<7>` 标签，逐帧看相邻元素交换如何把最大值推到右端，每帧配一段编号文字，卡住的那一步就停在那里读；
3. 滚动到代码块，对照正文确认内循环边界 `for j in range(i)` 与未排序区间 `[0, i]` 的对应关系；
4. 点击代码块下方的"可视化运行"，在 Python Tutor 里单步看 `flag` 优化提前跳出的时机；
5. 把 `codes/python/chapter_sorting/bubble_sort.py` 复制到本地跑一遍，再按标志优化版的思路，尝试手写一个"从右往左冒泡"的变体，对照仓库实现检查边界；
6. 做第 11 章末尾的练习题，有疑问就翻到章节底部评论区——评论区基于 giscus 挂在 GitHub 讨论区上，作者在"如何使用本书"里承诺一般两天内回复。

六步走完，图、文、码、执行、检验五个环节都碰过一遍。这正是序章里作者引用的那句费曼话的注脚——"Knowledge isn't free. You have to pay attention."——本书的设计就是让这份注意力花在过程上，而不是花在配环境、找依赖上。

## 多语言文档：五套独立站点

仓库顶层除了简体中文的 `docs/`，还平铺着四份结构相同的独立文档树：`zh-hant/`、`en/`、`ja/`、`ru/`，每份都有自己的 `docs/` 和 `mkdocs.yml`。根目录的 Dockerfile 揭示了构建方式：五套文档树被逐个 `mkdocs build` 成独立站点，网页页头通过 Material 主题的 `alternate` 配置在五种语言之间切换。

对中文读者来说，简体中文版是源头和最新版本；其余四种语言由社区志愿者转译并独立维护，更新节奏取决于各语言的贡献者。发现译文陈旧，可以在对应语言的文档树里提 PR，或到 Issue 区反馈。

## 贡献路径

项目的贡献入口有两条，成本差别很大：

- **内容微调**（改错字、修笔误、补注释）：每个网页页面右上角有编辑图标，点击直接跳到 GitHub 的文件编辑页，改完提交即可发起 PR，走的是最小摩擦路径。
- **内容创作**（转译代码、扩展章节）：官方要求走完整流程——Fork 仓库、本地修改并完整测试、验证代码正确性后再发 PR。

多语言代码转译由 [issue #15](https://github.com/krahets/hello-algo/issues/15)（Code Transpilation to multiple programming languages，截至 2026-10 仍开放，73 条讨论）统一协调：想给项目添加新语言，先在 issue 里认领，再按章节逐个转译。该 issue 推荐以 Python 或 Java 作为参照实现。已转译文件的头部都保留着转译者的署名和时间戳（如 `Author: timi (xisunyy@163.com)`），14 种语言就是这样一门一门凑出来的。

想搭一套本地站点，根目录 `docker-compose up -d` 一条命令，构建后访问 `http://localhost:8000`。

## 值得参考的几个设计点

- **分步帧替代自动动画**：把过程控制权交给读者，同样一张图，学习效率不同；代价是作者的画图工时。
- **代码纪律先于工程设施**：不靠脚手架保证可运行，靠"只用标准库 + 自带测试入口"的约定，14 种语言都遵守同一纪律。
- **文档与代码同名配对**：`bubble_sort.md` 与 `bubble_sort.assets/`、`codes/*/chapter_sorting/bubble_sort.py` 三方一一对应，读者在三个层面之间切换零查找成本。
- **构建产物不入库**：五套文档树都是源文件，`mkdocs build` 的产物放在构建层的 `build/` 目录（如 Docker 镜像内），git 历史里只有源 Markdown 和图片源文件。
- **顶层平铺多语言**：每语言一棵完整文档树、独立构建，贡献者不需要理解嵌套的 i18n 目录约定。

## 练习

**练习 1：走完一次完整学习路径**

1. 打开网页版第 11 章冒泡排序，用步骤标签逐帧看完 7 步交换过程。
2. 点击"可视化运行"，在 Python Tutor 里对比 `bubble_sort` 与 `bubble_sort_with_flag` 在有序输入上的执行步数差异。
3. 把 `bubble_sort.py` 复制到本地运行，修改 Driver Code 的输入，观察标志优化在部分有序数组上的表现。

**练习 2：跨语言对照**

1. 选一个你熟悉的算法（如二分查找），对照它的 Python 与 Rust 实现，比较两版的错误处理方式。
2. 用第三门语言重写该算法，保持"只用标准库、自带测试入口"的纪律。

**练习 3：参与一次贡献**

1. 阅读时留意错别字、笔误或代码问题，通过页面右上角编辑图标直接提 PR。
2. 想练手转译，到 issue #15 查看语言认领情况，留言认领一门未完成的语言。

## 进阶路径

1. **按导航顺序读完第 0～15 章**：不跳过复杂度分析，每章的练习动手做，选读章节（`*` 标题）第一遍可跳过。
2. **进入阶段二**：配合 [LeetCode-Book](https://github.com/krahets/LeetCode-Book) 的题单开刷，按遗忘曲线安排 3～5 轮复习。
3. **合上书重写关键算法**：排序、二分、堆操作、DP 经典题，写完对照仓库实现检查边界。
4. **从读者到贡献者**：修错字、审阅翻译、认领转译，都是低门槛入口。
5. **走向更深**：学完后再读《算法导论》或竞赛教材，补高级数据结构与专题。
