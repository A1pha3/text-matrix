# Vorssaint 拆解：一个菜单栏图标装下一打付费 Mac 工具

## 核心判断

Vorssaint 的本质是**把 Mac 用户习以为常的"买一个 App 解决一个问题"模式，替换成"一个宿主 + 可装卸功能模块"的模式**。音量混合、窗口管理、剪贴板历史、截屏录制、应用卸载——这些在 App Store 里通常各卖 30 到 100 元的工具，在同一个菜单栏图标后面协同工作，GPL-3.0 开源，本地运行，无账号无遥测。

它最值得看的不是功能数量，而是一个工程决策：**功能是运行时可装卸的**。你卸载一个功能，它从整个应用中消失、停止加载、不再消耗 CPU 和内存——这不是"隐藏图标"式的话术，而是把模块化做进了运行时。

## 系统地图：六个能力域

README 按使用场景划分功能，本文按系统触达方式重新归类——因为一个菜单栏工具的真实成本在于它向 macOS 申请了多少权限：

| 能力域 | 代表功能 | 依赖的系统权限 |
|--------|----------|---------------|
| 声音 | 每应用音量混合、单应用输出路由、麦克风静音 | 系统音频录制 |
| 系统监视 | CPU/GPU/温度历史图、网络测速、菜单栏读数 | 无（读取系统信息） |
| 窗口与 Dock | 增强版 ⌘Tab 切换器、窗口吸附、Dock 缩略图预览 | 辅助功能、屏幕录制 |
| 键盘鼠标 | 文本展开、平滑滚轮、Super 键、按键去抖 | 辅助功能 |
| 剪贴板与文件 | 剪贴板历史、文件 Shelf、追踪参数清理、磁盘镜像安装器 | 辅助功能 |
| 日常工具 | Command Bar、截屏录制、Cleaner、卸载器、Homebrew 管理 | 视功能而定 |

这个归类暴露了一个事实：菜单栏工具箱是**权限密集型**应用。Vorssaint 对此的回应值得单独说（见下文"权限的诚实呈现"）。

## 关键机制一：功能可装卸

大多数"工具箱"应用的问题是无差别的臃肿——你只为剪贴板历史而来，却带着整个视频编辑器在后台跑。Vorssaint 的 Features 页面安装和卸载的是**整个功能**：

- 卸载即消失：从面板、快捷键、菜单栏中全部移除，不再加载，不耗 CPU、内存、电量；
- 状态保留：卸载不删数据，重装后设置原样回来；
- 首次设置给三个一键组合（Essentials / Windows / Battery and quiet）加可视化单项选择器，只申请所选功能需要的权限；
- 每个功能带"诚实能耗徽章"，标注它在开启状态下让什么保持活跃。

这个设计同时解决了两个矛盾：用户"只想要三分之一功能"的诉求与应用"功能即卖点"的倾向。对开源桌面应用来说，这是少见地把"按需安装"从发行版层面（Homebrew formula 拆分）下沉到了应用内部。

## 关键机制二：Command Bar 作为统一入口

功能多了以后，入口本身成为瓶颈。Command Bar（快捷键呼出的全局命令栏）承担了统一调度：输入几个字母可以执行任意 Vorssaint 动作、打开应用、切换窗口、插入表情或 snippet、从剪贴板历史粘贴，甚至"伸进"当前应用执行其菜单里的命令并显示原生快捷键。它还能就地回答算术、单位换算、日期和"关于这台 Mac"的问题，检索逻辑是"学习最常用的，忘掉输入过的"——即用即弃，不留索引。

对文本工作流用户，这接近把 Raycast / Alfred 的一角吸收了进来；区别在于它只调度本地已有能力，不引入插件生态。

## 权限的诚实呈现

macOS 权限对话框是用户信任的漏斗。Vorssaint 的 Permissions 页面做三件不常见的事：每个权限用平实语言解释用途；展示**哪些功能实际在使用它**；当某个已授予权限不再被任何功能需要时主动提醒你，并给出撤销入口。配合本地优先原则——无账号、无分析、无追踪，网络请求仅限可见的几项（更新检查、测速、Homebrew 操作、临时分享链接）——它把"权限最小化"从口号变成了可操作界面。

## 快速上手

```sh
brew install --cask vorssaint
```

或从 releases 页下载 dmg 拖入 Applications。构建有 Developer ID 签名和公证，Gatekeeper 不拦截，升级保留权限。完整卸载用仓库内的 `./Tools/uninstall.sh`。

## 取舍与边界

**选它的理由**：一次性替代多个单功能付费工具（音量混合器、窗口管理器、剪贴板工具、截屏工具、卸载器），数据不出机器，模块化让常驻开销可控。

**不选它的理由也要直说**：

- macOS 14+ 且仅 Apple Silicon——老 Intel Mac 直接排除；
- GPL-3.0 对想借鉴代码做闭源工具的开发者不友好；
- 单应用承载数十功能，虽然可卸载，但默认组合的内存占用仍高于单一专用工具；
- 项目 2026-06 才创建，三个月冲到 1.5 万星，功能面铺得很宽，单个功能的深度与老牌专用工具（如 Bartender 之于菜单栏管理）孰优孰劣，需各自验证；
- 处于 beta 节奏（v3.3.3-beta.4），稳定性以 release 为准。

**适用人群**：愿意用一个开源应用整合日常工具链、对订阅制疲劳、且硬件符合要求的 Mac 用户。已经在 Raycast + 一组专用工具上建立满意工作流的人，迁移收益需要自己权衡。

## 本文不覆盖什么

各功能与付费竞品（Bartender、CleanShot X、Alfred 等）的逐项对比、性能实测数据，仓库未提供基准材料，本文不做无依据的优劣断言。Fan Control 等标注 beta 的功能细节以其官方文档为准。
