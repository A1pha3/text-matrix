# Claude 101 第一课：认识 Claude——它是谁，能做什么

> 预计阅读时间：15 分钟 | 难度：⭐⭐

> **目标读者**：第一次接触 Claude，想搞清它是什么、能干什么、从哪里开始的新手
> **核心问题**：Claude 到底是什么？它能帮我做什么？我该从哪个入口开始用？
> **前置知识**：无，零基础可读

---

## 学习目标

学完本节后，可以：

- 说清 Claude 是什么、不是什么，避免把它当成"万能工具"。
- 列出 Claude 的常用入口，知道第一次打开该从哪个开始。
- 判断手头任务适合交给 Claude，还是更适合搜索引擎或其他工具。
- 掌握与 Claude 协作的四个基本习惯，亲身体验"上下文"的作用。

---

## Claude 是什么？

**Claude** 是 Anthropic 开发的 AI 助手。它读懂自然语言、跟随上下文、通过对话协助你完成工作——更像一位可以反复讨论的数字同事，而不是返回一堆链接的搜索框。

它尤其适合这几类工作：

- **理解与整理信息**：总结长文、提炼会议纪要、梳理要点。
- **生成与改写内容**：起草邮件、润色文案、调整语气、搭建初稿。
- **分析与思考**：比较方案、拆解问题、头脑风暴、提供多个视角。
- **解释与教学**：把复杂概念讲给不同的人听。
- **支持技术工作**：解释代码、定位问题、协助写脚本或文档。

这些工作有个共同点：**都依赖理解、表达、组织和推理，不依赖实时操作真实世界。**

### 它怎么对待你的请求

Claude 的一个明显特点，是回答风格偏向可合作和克制。理想状态下，它会努力做到：

- **有帮助**：尽量贴近你的任务目标。
- **诚实**：不确定时承认不确定。
- **安全**：避免明显有害或不当的输出。

这不代表它永远正确，但意味着它通常更适合进入真实工作流，而不是只做娱乐型聊天。

### Claude 不是什么

要用好 Claude，先建立正确预期。它不是下面这些东西：

| 常见误解 | 更准确的理解 |
| :--- | :--- |
| "Claude 就是搜索引擎" | 它更像会读材料、会组织语言、会和你来回协作的助手 |
| "Claude 什么都知道" | 它可能出错，也可能对最新信息不了解 |
| "Claude 会自己把事情做完" | 默认情况下，它只能生成内容和建议，不能替你点击按钮或完成现实操作 |
| "Claude 能替我做判断" | 它能帮你分析，但最终责任仍然在你 |

## 在哪里使用 Claude

Claude 有几种入口，从轻到重，各有适合的人群：

| 入口 | 适合谁 | 典型用途 |
|------|--------|----------|
| 网页版 [claude.ai](https://claude.ai) | 所有人 | 问答、写作、总结，打开就能用 |
| 桌面应用 | 想把 Claude 放进日常工作的用户 | 除对话外，还提供 Chat / Cowork / Code 三种工作方式 |
| 移动端 App | 通勤、随手记录 | 语音、拍照、随手提问 |
| API | 开发者 | 把 Claude 的能力接进自己的产品 |
| Claude Code | 开发者 | 在终端里读代码库、改文件、跑命令 |

第一次使用，从**网页版或桌面应用的 Chat** 开始最省事，不需要懂任何技术概念。桌面应用的三种工作方式怎么选，见本系列《[Claude 桌面应用：Chat、Cowork、Code]({{< relref "claude-101-meet-claude-desktop-app.md" >}})》。

> 各入口的具体功能、可用范围与定价会随官方更新而变化，以 [Anthropic 官网](https://www.anthropic.com/) 和 [claude.ai](https://claude.ai) 当前页面为准。

## Claude 最适合做什么？

如果你是刚开始用，可以从这些高回报场景入手：

| 任务类型 | 适合原因 | 你可以这样开口 |
| :--- | :--- | :--- |
| 写作与润色 | Claude 很擅长改写语气、结构和表达 | "请把这封邮件改成更专业但不生硬的语气。" |
| 总结与提炼 | 它能快速从长材料里提取重点 | "请把这份会议记录整理成结论、风险和待办事项。" |
| 解释与教学 | 它可以按对象调整表达难度 | "请用面向新人的方式解释这份方案。" |
| 头脑风暴 | 它能快速给出多个思路和角度 | "请给我 5 个不同方向的选题，并说明各自优缺点。" |
| 分析与比较 | 它适合先搭出分析框架 | "请比较 A 和 B 两种做法，从成本、速度、风险三方面展开。" |
| 技术辅助 | 它能解释代码、帮你重构思路 | "请阅读这段代码，先解释问题，再给出改进方案。" |

## Claude 是如何工作的？极简理解版

不需要理解模型细节也能先用起来，但知道一点基础原理，能帮你提问。

### 1. 它根据你的输入"生成"回答

Claude 根据你给的内容、上下文和训练中学到的语言规律，实时生成一段最合理的回应，而不是在数据库里翻出标准答案。这意味着两件事：

- 同一个问题，换一种提法，结果可能明显不同。
- 你给的背景越充分，回答通常越贴近你的真实需求。

### 2. 它对"上下文"非常敏感

Claude 读到的不只是你最后一句话，还包括：

- 前面几轮对话里你说过什么
- 你刚贴进去的材料是什么
- 你要求的角色、格式、语气、限制条件是什么

所以，**好结果往往来自给到足够好的上下文，而不是问到一个神奇问题。**

### 3. 它会受到安全规则与能力边界的约束

Claude 会尽量避免某些有害请求，也会在部分问题上表现得更保守。同时它依然会犯错、会遗漏、会误解你的意图。这就是为什么使用 Claude 时，最好的姿势是协作 + 复核，而不是盲信。

## 什么时候不该用 Claude？

以下场景里，Claude 可以参与，但通常不应成为最终依据：

| 场景 | 为什么不适合？ | 更好的替代方案 |
| :--- | :--- | :--- |
| 查询刚刚发生的新闻、价格、政策 | 信息可能不是最新的 | 搜索引擎、官方公告、专业数据库 |
| 需要你本人确认的专业结论 | Claude 可能说得很像对，但并不等于真实可靠 | 医生、律师、财务顾问、正式审批流程 |
| 涉及高敏感或受限数据 | 并非所有信息都适合直接粘贴到公共 AI 工具 | 公司合规流程、受控环境、脱敏处理 |
| 需要真实执行系统动作 | 它可以教你怎么做，但默认不会替你完成操作 | 对应软件、自动化系统、人工执行 |
| 必须 100% 精确的数值或事实 | 语言模型擅长"合理表达"，不等于"绝对精确" | 计算器、代码、原始数据、权威来源 |

## 使用 Claude 的正确姿势

真正高效的用户，通常是掌握了下面 4 个习惯的人，而不是问得最花哨的人。

### 1. 先交代背景，再提任务

不要只说"帮我写一下"或"你怎么看"。更好的方式是补充这些信息：

- 你是谁
- 你要做什么
- 你的受众是谁
- 你有哪些限制
- 你希望输出成什么格式

### 2. 把它当作协作者，而不是一次性问答机

第一版回答不够好很正常。你可以继续说：

- "请更简洁一点。"
- "请改成邮件格式。"
- "请保留原意，但语气更坚定。"
- "请先指出问题，再给修改版。"

多轮迭代，通常比一次性憋出"完美提示词"更有效。

### 3. 对关键内容做复核

凡是涉及事实、金额、日期、法规、医学、代码依赖、外部引用的内容，都应该再次确认。Claude 可以帮你加速理解和整理，但不能替代最终核验。

### 4. 对敏感信息保持克制

在没有明确合规前，不要把客户隐私、未公开财务数据、合同全文、密钥口令等信息直接贴进去。必要时，先做脱敏处理。

## 常见问题

### Q1：Claude 会出错吗？

**会。** 它是语言模型，擅长"说得合理"，不等于"说得准确"。涉及事实、金额、日期、法规、代码依赖时，一定要复核。这不是提醒你少用，而是提醒你把它当助手、不当裁判。

### Q2：第一次用，该从哪个入口开始？

**网页版或桌面应用的 Chat。** 不需要任何配置，打开就能问。先做一两个小任务，等熟悉了再考虑更重的入口。

### Q3：Claude 和搜索引擎是什么关系？

**互补。** 搜索引擎返回链接，由你自己判断；Claude 直接给整理好的答案，但也可能出错。查最新、最有时效性的信息（刚发布的新闻、实时价格）时，两者配合更稳妥。

### Q4：我可以把隐私数据贴给 Claude 吗？

**谨慎。** 除非确认合规，否则不要把客户隐私、密钥口令、未公开财务数据直接贴进去，必要时先脱敏。具体数据处理方式，以 Anthropic 官方隐私政策为准。

## 术语表

| 英文 | 中文 | 说明 |
| :--- | :--- | :--- |
| **LLM (Large Language Model)** | 大语言模型 | 一类通过大量文本训练出来的模型，擅长理解和生成语言。 |
| **Prompt** | 提示词 | 你发给 Claude 的指令、问题或背景信息。 |
| **Context** | 上下文 | Claude 在当前任务里能看到并据此回答的背景信息。 |
| **Hallucination** | 幻觉 | 回答看起来合理，但其中事实、引用或细节并不可靠。 |
| **Iteration** | 迭代 | 通过多轮追问和修正，逐步把结果打磨到可用。 |

## 动手练习

读完这节后，建议你立刻做下面 3 个练习，建立对 Claude 的直观感受：

1. **认识能力边界**：问 Claude 一个与你最近工作相关的问题，再追问一句："请说明哪些地方是你确定的，哪些地方需要我自行核实。"
2. **体验上下文价值**：先只发一句模糊请求，再补充背景、目标和输出格式，对比两次回答的差异。
3. **试一次真实工作流**：把一段你自己写的邮件、笔记或文案贴给 Claude，请它分别输出"润色版""精简版""更正式版"。
