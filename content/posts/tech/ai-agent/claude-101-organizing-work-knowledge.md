## 这一篇对应官方课程的哪几节

官方 Claude 101 课程在 "Organizing your work and knowledge"（组织你的工作与知识）章节下安排了三节课：第 5 课 Introduction to projects（项目入门）、第 6 课 Creating with artifacts（用 Artifacts 创作）、第 7 课 Working with skills（使用技能）。这三节讲的是同一件事的三面——长期上下文、结构化产出、能力扩展，本文把它们合并成一篇导读，方便一次看全。

学完本文，你可以：

- 说清 Project、Artifact、Skill 各自解决什么问题，不再混着用
- 动手建一个项目：铺知识库、写项目指令，让 Claude 记住你的工作背景
- 让生成的内容成为可保存、可迭代、可分享的 Artifact，而不是聊天记录里的一段文字
- 启用官方技能或上传自己写的技能，让 Claude 直接产出 PPT、Word 这类成品文件

## 为什么你需要「组织」这件事？

在讲工具之前，先回答一个前提问题：**为什么用 AI 助手需要「组织」？**

想象一下，你请了一位能力很强的助理。但每次你去找他，他都不记得：

- 你上次跟他讨论的项目是什么
- 你们之前达成了什么结论
- 你给他看过的文件在哪里
- 你的偏好和工作习惯是什么

结果每次你都要从头解释一遍，效率极低。

普通的 AI 对话就是这样——每次新建对话，模型就「失忆」了，它不记得你上次说了什么，更不知道你的项目背景。

Claude 的 Projects、Artifacts 和 Skills 就是为这个问题设计的。它们让 Claude 从「一次性的问答机器」，变成能记住上下文、持续产出、可扩展能力的长期工作伙伴。

## 一、Projects（项目）：给长期工作一个固定场所

### 什么是 Project？

**Project** 是 Claude 提供的独立工作区：每个项目有自己的聊天记录和知识库。你把相关文档传进去、写好项目指令，之后的每次对话都能直接用上这些背景。

这里有一个容易误解的地方：项目内的各次对话**并不会自动互相看到**。Claude 官方帮助文档写得很明确——除非信息进入了项目知识库或项目指令，否则这次对话里的内容，下次对话并不知道。真正跨对话共享的是两样东西：**项目知识库**（你上传的文档、文本、代码）和**项目指令**（你对 Claude 在这个项目里如何回答的要求）。

### 为什么需要 Project？

用一对场景来理解：

**没有 Project 的日常**：

```text
你：我们在做一个面向自由职业者的记账 App，目标用户是设计师和摄影师，
    请帮我写一段应用商店的介绍文案。
（第二天，新对话）
你：嗯……我们在做一个记账 App，面向自由职业者，主要用户是设计师和摄影师，
    上次你写的文案不错，这次帮我把简介压缩到 80 字以内。
（背景要自己再讲一遍，讲漏一句，输出就偏一次）
```

**有 Project 的日常**：

```text
（项目知识库里已经放着产品定位文档和竞品清单，
  项目指令里写明了目标用户和文案风格）
你：把商店简介压缩到 80 字以内，保留「一键导出报表」这个卖点。
Claude：（直接基于项目背景输出，不需要你再解释产品是什么）
```

### Project 的核心能力

| 价值维度 | 具体说明 |
|----------|----------|
| **知识沉淀** | 上传的文档、文本、代码进入项目知识库，项目内所有对话共享 |
| **指令定制** | 项目指令规定 Claude 的语气、角色和输出要求，对该项目所有对话生效 |
| **大容量上下文** | 付费计划下，知识库接近上下文上限时会自动启用 RAG 检索，容量可扩展至约 10 倍 |
| **团队协作** | Team 与 Enterprise 计划可以把项目共享给同事，分「可使用」「可编辑」两级权限：前者能看到内容并参与对话但不能修改，后者可以维护指令与知识库 |

### 如何创建一个 Project？

创建入口很直接：在 claude.ai 左侧栏悬停找到 "Projects"，或直接访问 claude.ai/projects，点右上角 "+ New Project"，起一个名字、写一句描述即可。所有计划都能用，免费账户最多建 5 个项目。

值得注意的细节：**项目名称和描述 Claude 本身看不到**，它们只是给你自己看的标签。真正要喂给 Claude 的背景，要放进下面两个地方。

**把材料放进项目知识库**：项目主页右侧就是知识库，点 "+" 上传相关文档、文本或代码。这些内容会被自动用于该项目内的所有对话。

**写好项目指令**：

```text
（点项目主页上的 "Set project instructions"，填入类似这样的内容）

角色：你是这款记账 App 的产品文案助手。
语气：简洁、口语化，避免营销腔。
硬性要求：所有面向用户的文案，句子不超过 25 个字；
          必须出现「一键导出报表」功能时使用官方名称，不要简写。
```

保存后，项目里的每次对话都会自动带上这些要求，不用重复输入。

**从现有对话迁移**：把一段长期对话升级成项目，没有一键迁移按钮，做法是手动整理——把对话里达成的结论写进项目指令，把反复引用的材料上传到知识库。整理的过程也是校验的过程：哪些背景是稳定的、哪些只是一次性的，分开之后项目才干净。

### Project 的推荐做法

#### 按「工作域」划分项目

不要把所有事情都塞进一个 Project。建议这样组织：

| Project 名称 | 包含内容 |
|-------------|----------|
| 📚 我的读书计划 | 所有读书笔记、书评、读后感 |
| 💼 产品经理工作台 | PRD、竞品分析、用户研究 |
| 🛠️ 独立开发项目 | 代码、架构文档、技术方案 |
| 📝 个人博客 | 所有博客文章、选题灵感、草稿 |

按工作域而不是按任务划分，是因为知识库的价值在于积累——「写某篇 PRD」是一次任务，「产品经理工作台」才是能沉淀竞品资料、写作口径的地方。

#### 定期「整理」项目

Project 不是一次性工具，需要定期维护：

- **每周回顾**：花 5 分钟回顾本周在项目中的进展
- **归档完成的任务**：把已经完成的工作归档，保持项目整洁
- **更新上下文**：如果项目方向调整，及时更新知识库和指令

> 补充一句时效口径：2026 年 9 月 17 日，Anthropic 发布了重新设计的 Projects（官方博客标题「从文件夹到对话」），beta 首批面向使用 Claude Code 云端会话的 Pro / Max 用户。新版里一个项目由两类角色组成：一个 coordinator（协调者）接收你的目标并拆解工作，多个 thread（线程）并行执行——每个线程都是一个独立的 Claude Code 云端会话，在自己的分支和代码副本上工作。所有线程共享一份随项目积累的记忆，减少重复交代背景。截至 2026 年 9 月下旬，新版仍在小范围灰度，多数用户用的还是本文描述的现有版本，新旧功能细节以官方帮助文档为准。

## 二、Artifacts（产物）：让生成的内容独立存在

### 什么是 Artifacts？

**Artifacts** 是 Claude 在对话中生成的、值得单独保存和分享的成果。官方帮助文档的定义很朴素：一件「你会拿给别人看」的东西——设计稿、演示文稿、文档、仪表盘，或者一个小型交互工具。它出现在对话旁边的独立窗口里，可以编辑、可以回访、可以用链接分享。

Claude 不是把所有回复都变成 Artifact。官方给出的判定标准是：内容足够重要且自成一体（通常超过 15 行）、你之后可能会编辑或复用、不需要结合对话上下文也能独立读懂。常见的 Artifact 类型包括：Markdown 或纯文本文档、代码片段、单页 HTML 网站、SVG 图像、图表与流程图，以及交互式 React 组件。

### 为什么需要 Artifacts？

普通的 AI 回复「活在」聊天记录里，你想要就得复制粘贴走。如果内容需要更新，你得记住是哪次对话、找到那条消息、重新复制。Artifact 改变的是这个流程——内容有了独立的位置，可以一键复制、实时预览、持续迭代，也可以直接分享链接给别人。

### Artifacts 的典型使用场景

#### 代码片段与小工具

```text
你：帮我做一个 Markdown 表格转 CSV 的网页小工具，粘贴进去就能预览转换结果。
（Claude 生成的单页 HTML 会以 Artifact 形式出现在对话右侧——
  超过 15 行、自成一体，正是它判定为 Artifact 的内容。
  你可以直接预览运行效果，让它改细节，满意后复制或分享链接）
```

#### 网页 / UI 原型

```text
你：为一个冥想 App 的落地页做一个原型：顶部是产品口号，
    中间是三个功能卡片，底部是下载按钮，整体用安静的深绿色调。
（原型直接可预览。你可以指着具体元素继续提要求：
  「把口号换成这句话」「卡片改成两列」）
```

#### 文档和文章

```text
你：把我们刚才讨论的产品方案整理成一份结构化文档：
    背景一节、目标一节、里程碑表格、风险清单。
（长文档适合做成 Artifact：独立可读、方便迭代，不必在聊天记录里翻找）
```

### Artifacts vs 普通回复：核心区别

| 维度 | 普通回复 | Artifacts |
|------|----------|-----------|
| **持久性** | 淹没在聊天记录里 | 独立存在，侧边栏 Artifacts 区随时回访 |
| **可编辑性** | 只能复制走 | 对话里让它改，或直接在成品上编辑 |
| **可分享性** | 截图或复制粘贴 | 生成链接一键分享；官方支持公开分享、嵌入网页，也可只发给特定的人 |
| **适用内容** | 简短回答 | 代码、文档、原型等成体系的内容 |

### 如何高效使用 Artifacts？

#### 让 Claude「迭代」Artifact

Artifact 的价值在迭代。第一版不用追求完美，先让 Claude 出来，再逐步收紧：

```text
第一轮：先做一个只有核心功能的版本。
第二轮：表格在手机上会横向溢出，改成可折叠的布局。
第三轮：把报错提示都换成中文，并在出错时给出修正建议。
```

对 Markdown 文档，还有更精确的改法：在成品里选中要改的那段文字，点 "Edit with Claude" 输入要求，Claude 只改你圈定的位置。

#### 给 Artifact 定标准

生成之前就把质量标准说清楚，比事后返工省事：

```text
你：这个仪表盘按「可以直接放进周报」的标准来做——
    图表要有坐标轴标签，数字保留一位小数，配色只用蓝灰两色。
```

#### 版本回溯

Artifact 更新多轮之后想分享旧版本，不需要手动存档：分享链接时可以选择链接指向「最新版本」还是「某个指定版本」。分享最新版，对方看到的是你的后续修改；指定版本则固定不动。

#### 让产物进入侧边栏区

对话里生成的 Artifact **不会自动出现在侧边栏**的 Artifacts 区。打开想保留的产物，点窗口里的 "Publish" 才会收进去——之后可以在侧边栏统一浏览、回访，也才能嵌入网页或公开发布。需要长期留用的成果，养成「生成后顺手 Publish」的习惯。

> 使用前提：Artifacts 需要 Claude 开启代码执行与文件创建能力（Settings > Capabilities 里的 "Code execution and file creation"）。另外还有一套 beta 工具——Claude Design（设计稿）、Claude Slides（演示文稿）、Claude Docs（文档），适合对排版要求更高的场合。2026 年 9 月 16 日 Cowork 与对话合并为统一的 Claude 之后，这三件工具都能在对话内直接使用，产出同样归入 Artifacts 体系；此前它们只在独立工作区里可用。

## 三、Skills（技能）：给 Claude 装上专业模块

### 什么是 Skills？

**Skills** 是给 Claude 扩展能力的模块：每个技能封装一套专业知识或工作流程，让 Claude 完成原本不擅长的特定任务。

先分清两个容易混淆的概念。Claude 有一类内置**能力**（capabilities），比如联网搜索、代码执行，它们决定 Claude「能做什么动作」；而 Skills 是更完整的**本领**，每个技能自带操作指南和配套资源。你在 Claude 里能直接使用的官方示例技能有四件：

- **Excel 表格**：创建与处理电子表格
- **Word 文档**：生成专业排版的文档
- **PowerPoint**：制作演示文稿
- **PDF**：生成与处理 PDF 文件

### 为什么需要 Skills？

#### 没有 Skills 的局限

```text
你：把这份季度数据做成一份汇报用的 PPT。
Claude：好的，以下是我建议的 PPT 大纲：第一页放封面……
（它只能给你文字大纲和逐页讲稿，给不了一个真正的 .pptx 文件）
```

#### 有 Skills 的能力

```text
（开启代码执行与文件创建能力、启用 PowerPoint 技能后）
你：把这份季度数据做成一份汇报用的 PPT。
Claude：（直接生成可下载的 .pptx，图表、配色、版式都已就位，
        你可以继续对话让它调整）
```

### Skills 的工作原理

官方帮助文档对使用方式的描述只有一句：**你不需要显式调用**。开启之后，Claude 会根据你的请求自动判断该用哪个技能——你说「做一份关于 Q3 结果的 PPT」，它检测到演示文稿需求，就会自动用上 PowerPoint 技能。

技能本身是一个文件夹，里面有一份 SKILL.md 清单文件描述「这个技能做什么、什么时候用、怎么用」，外加配套的参考材料和脚本。Claude 平时只读每份技能的简介（很省上下文），判断当前任务匹配后才加载完整内容。这套结构是开放的——Agent Skills 已成为跨产品的开放规范，站内这篇《[Agent Skills 开放规范解读](/posts/tech/agent-skills-ai-agent-open-specification-guide/)》有逐层拆解。

### 官方内置技能一览

| 技能 | 能力 | 使用场景 |
|------|------|----------|
| **Excel** | 创建与处理电子表格 | 数据整理、带公式的报表 |
| **Word** | 生成 .docx 文档 | 正式文档、报告排版 |
| **PowerPoint** | 生成 .pptx 演示文稿 | 汇报、课件、提案 |
| **PDF** | 生成与处理 PDF | 合同、说明书、格式转换 |

联网搜索、网页读取、代码执行这些属于上面说的「能力」，在 Settings > Capabilities 里开关，与技能是两回事。

### 如何使用 Skills？

#### 开启与关闭

个人计划（Free / Pro / Max）的路径是：Settings > Capabilities 打开 "Code execution and file creation"，再到 Customize > Skills 里逐个开闭技能。Team 计划的组织层面默认启用，成员在 Customize > Skills 里开关即可；Enterprise 计划需要管理员先在 Organization settings > Skills 开启，管理员还可以把技能配置给全组织成员。

> 时效口径：Skills 目前要求代码执行能力开启才可用；Claude Code 与 API 场景下处于 beta 或需要搭配代码执行工具。以官方帮助文档的当前说法为准。

#### 自己动手写一个

官方四件套之外，你可以把自己常用的工作流写成技能：按 SKILL.md 结构建文件夹，打包成 ZIP，在 Customize > Skills 里点 "+" 上传。上传的技能默认只有你自己可见，Team 与 Enterprise 计划内可以分享给同事、群组或全组织——共享出去的技能对接收者是只读的，他们只能启用和使用、不能改内容，你之后更新，对方下次使用时自动拿到新版本。写作规范见站内的开放规范解读一文。

#### 组合使用

```text
你：读取我上传的用户访谈记录，归纳高频痛点，
    然后把结果做成一页可分享的摘要文档。
（一次请求里，代码执行负责处理上传的文件，
  归纳靠模型本身，产出落在 Artifact——多种能力协作完成同一件事）
```

## 四、三者的协同价值：完整的「人机协作」工作流

### 为什么它们组合在一起更强大？

Projects、Artifacts 和 Skills 不是孤立的功能，三者拼出一条完整的链路：

```text
Projects：记住你是谁、在做什么（背景与知识的沉淀）
Skills：  决定 Claude 能完成哪些专业动作（能力的扩展）
Artifacts：把每一步产出变成可保存、可迭代的成果（成果的沉淀）

一次任务里三者齐动：项目提供背景 → 技能扩展能力 → 成果进入
Artifacts 区；下一次任务接住上一次的积累，而不是从零开始。
```

### 实战场景：用 Claude 完成一本书的写作

**场景**：你要写一本关于「AI 时代个人成长」的书。下面是三个功能各自的位置——具体产出因人而异，这里给出的是可照抄的流程框架。

#### 第一步：建项目、铺背景（Projects）

```text
新建项目「书稿：AI 时代个人成长」。
知识库上传：选题策划案、三章样章、你认可的文风示例。
项目指令写明：本书面向有两年 AI 使用经验的职场读者；
              每章开头用一个小故事切入；全书避免堆砌术语。
```

#### 第二步：出大纲（Artifacts 承载结构）

```text
你：基于知识库里的选题策划案，出一份 12 章的完整大纲，
    每章给出核心问题和 3 个小节标题，做成一份文档 Artifact。
（大纲是典型的 Artifact：要反复改、每章写作时都要回看）
```

#### 第三步：逐章迭代（Artifacts 持续演化）

```text
你：写第三章初稿，对齐知识库里样章的文风，先出 3000 字。
你：第三章的案例太旧了，换成最近一年的产品实例，
    其余结构不动。
（每章一个文档 Artifact，改稿不再受聊天记录长度牵制）
```

#### 第四步：需要成品的场合交给 Skills

```text
你：把第八章整理成一份 20 分钟的分享演示文稿。
（PowerPoint 技能自动接管，产出可直接下载的 .pptx）
```

#### 第五步：交付与整理（Artifacts 导出）

```text
书稿定稿后，从 Artifacts 区逐份导出；
分享链接发给编辑评审；评论区反馈再拉回对话里继续改。
```

这条工作流的价值不在某一步多聪明，而在每一步都留在了体系里：下一本书、下一次改版，背景和成果都还在。

## 五、常见问题与推荐做法

### Project 太多了怎么办？

**建议**：按「工作域」而不是「任务」来组织 Project。

- ❌ 一个 Project 叫「写 PRD」
- ✅ 一个 Project 叫「产品经理工作台」，包含所有产品相关工作

### Artifact 太多，找不到想要的怎么办？

**建议**：Claude 侧边栏有专门的 Artifacts 区，所有产物集中在一处，可以统一浏览、从模板新建、整理归组。日常配合两个习惯：给 Artifact 起描述性的名字（「用户访谈摘要 9 月」比「文档 3」好找得多），定期清理不再需要的产物。

### Skills 会不会泄露我的隐私？

**说明**：

- 内置技能的触发不需要逐次授权，Claude 判断任务匹配就自动使用；是否启用某个技能由你在 Customize > Skills 里控制
- 自己上传的技能默认仅本人可见，分享给谁、是否全组织开放，都由你决定
- Team 与 Enterprise 计划由管理员在组织层面统一管控技能的启用与共享；对隐私敏感的团队，这是一道组织级闸门
- 官方对技能的安全口径值得留意：技能可能附带第三方包或脚本，官方明确提示的主要风险是提示注入（prompt injection）与数据外泄，建议只从可信来源安装技能，启用他人分享的技能前先读一遍技能文件内容，重点关注其中的代码依赖和联网动作

### 应该把所有东西都放在 Claude 里吗？

**建议**：不要把 Claude 当成「存储服务」。

适合放进去的：

- 对话上下文和背景信息
- 正在进行的项目
- AI 帮你生成的草稿和内容

不适合放进去的：

- 机密文件（密码、密钥、私人数据）
- 大量历史文档（用文件管理工具管理）
- 不需要 AI 理解的纯存档

## 练习

### 创建你的第一个 Project

现在就创建一个 Project，叫「AI 学习笔记」，包含：

- 项目指令：说明你正在学习 Claude、目标是成为重度用户
- 知识库：上传一两份你觉得有用的笔记或文章
- 第一条对话：让 Claude 基于你上传的材料回答一个问题，观察它是否用上了背景

### 体验 Artifact 迭代

让 Claude 做一个小工具或一份文档，然后连续迭代至少 3 个版本，体验「在成品上持续修改」与「在聊天记录里翻找」的区别。

### 规划你的「人机协作」工作流

思考你日常最耗时的一项工作，尝试用 Projects + Artifacts + Skills 的组合设计一个优化方案：背景放哪、产出放哪、需要什么技能。
