# Minimalist Entrepreneur Skills 专题导读：原理、案例与 Prompt 模板一站看完

> 预计阅读时间：15 分钟 | 难度：⭐⭐

---

> 适合读者：想用 Claude Code 做早期创业验证，但不想只看概念、也不想只看空模板的人。
>
> 阅读目标：用最短路径建立正确顺序感，然后马上开始执行。

## 学习目标

这篇导读覆盖以下内容：

1. **理解这个专题的阅读顺序为什么不能乱**：知道“方法论 → 案例 → 模板”分别解决什么问题。
2. **根据自己的状态选入口**：判断自己更应该先读原理、先看案例，还是直接进入模板执行。
3. **识别适用边界**：知道这套专题更适合哪类早期项目，不适合拿来解决什么问题。
4. **把阅读转成行动**：读完后可以立刻决定自己接下来 1 步到 2 步该做什么。

## 先记住一个核心原则

这套专题解读的对象，是 Gumroad 创始人 Sahil Lavingia 开源的 [slavingia/skills](https://github.com/slavingia/skills) 仓库：他把《The Minimalist Entrepreneur》（2021）里的创业方法论做成了 10 个可直接调用的 Claude Code Skill。专题的其余三篇文章分别负责方法论拆解、案例推演和模板落地。

这个专题真正想解决的不是“给你更多创业灵感”，而是帮你建立一条**更不容易自我欺骗的执行顺序**。

很多技术型创业者的典型问题不是努力不够，而是顺序错了：

- 过早写代码，还没验证用户是否真痛。
- 过早做营销，还没有可持续交付的结果。
- 过早扩张，甚至还没证明第一批客户会持续留下来。

Minimalist Entrepreneur Skills 这组文章的价值，就在于把这些高频错误拆开，让你先判断**服务谁、解决什么、如何手工交付、如何收费、如何拿到首批客户**，再谈系统化和增长。

## 这个专题解决什么问题

如果你正在用 Claude Code 研究创业、做独立开发，最容易掉进两个极端：

- 只看方法论，觉得都懂了，但还是不知道今天该做什么。
- 只抄模板，Prompt 写得很像样，但实际上根本没有真实上下文。

这个专题的设计目标，就是把这两件事打通：

- 先让你理解 Minimalist Entrepreneur Skills 的底层顺序。
- 再让你看到这套顺序在真实约束里如何落地。
- 最后把方法和案例压缩成可直接复制的 Prompt 模板。

## 专题结构与阅读逻辑

这组文章一共 4 篇：本文是导读，其余 3 篇分别承担“方法论 → 案例 → 模板”三种角色。

| 篇目 | 定位 | 解决什么 | 适合谁 | 难度 / 篇幅 | 读完的直接产出 |
|------|------|------|------|------|------|
| 方法论篇 | 原理总览 | 10 个 Skill 是什么、为什么要按这个顺序用 | 第一次接触、还在找方向 | ⭐⭐⭐ / 40 分钟 | 知道现在最该先调用哪个 Skill |
| 案例篇 | 案例拆解 | 这套方法在真实约束里怎么落地 | 有方向但不知道怎么推进 | ⭐⭐⭐⭐ / 20 分钟 | 把“概念”翻译成“每周动作” |
| 模板篇 | 模板工具 | 今天打开 Claude Code 应该怎么输入 | 准备立刻开始跑 | ⭐⭐⭐ / 15 分钟 | 复制 Prompt 直接执行 |

三篇的职责可以压缩成一句话：第一篇校正方向，第二篇建立现实感，第三篇进入执行。

不建议跳过前两篇直接看模板。没有方向与边界，模板越像样，越容易把你带去错误方向。

## 10 个 Skill 一页速览

专题围绕 slavingia/skills 仓库里的 10 个 Claude Code Skill 展开。先记住分组：前 6 个偏“验证与成交”，后 4 个偏“增长、经营与决策”。

| 分组 | 命令 | 一句话作用 |
|------|------|------|
| 验证与成交 | /find-community | 先找人，不先找点子 |
| | /validate-idea | 用交易信号验证痛点，而不是靠点赞 |
| | /mvp | 收缩到本周能交付的最小结果 |
| | /processize | 不写代码，先把手工流程走通 |
| | /first-customers | 一个个人把前 100 个客户卖出来 |
| | /pricing | 收费本身就是验证动作 |
| 增长与经营 | /marketing-plan | 有客户语言之后，再做内容 |

| | /company-values | 定义这家公司“不成什么样” |
| | /minimalist-review | 任何复杂决策，回到极简原则复核 |

## 推荐阅读顺序

### 第一篇：先建立顺序感

读 [Minimalist Entrepreneur Skills 详解：把 Claude Code 变成创业决策操作系统]({{< relref "slavingia-skills-minimalist-entrepreneur.md" >}})，先弄清 10 个 Skill 分别解决什么问题、为什么不能乱序使用，以及 /mvp、/processize、/marketing-plan 之间最容易混淆的边界。

### 第二篇：再看它如何在真实约束里落地

读 [如何用 10 个 Minimalist Entrepreneur Skills 跑完一个真实约束创业案例]({{< relref "../slavingia-skills-real-startup-case.md" >}})，看一条从社区、验证、手工交付到首批付费的完整路径：8 周内每一步该做什么、不该做什么，以及技术型创业者为什么总是过早写代码、过早做营销、过早扩张。

> 说明：案例基于真实创业约束整理，人物与个别细节做了去标识化处理，但决策顺序、数据尺度和踩坑点都保留了下来，可以当成可直接照抄的执行脚本。

### 第三篇：最后直接复制模板开始做

读 [Minimalist Entrepreneur Skills 实战 Prompt 模板：从找社区到首批付费的可复制脚本]({{< relref "../slavingia-skills-prompt-templates.md" >}})，拿到 10 个 Skill 的直接可用模板、每个模板最关键的输入字段，以及一个帮你判断“当前该用哪个 Skill”的组合诊断模板。

### 时间有限时怎么读

- 只有 10 分钟：读方法论篇的“正确使用顺序”，再翻到模板篇的组合诊断模板，先判断自己卡在哪一步。
- 有 30 分钟：按顺序读方法论篇和案例篇，再复制模板篇里最适合你的那个模板。
- 有 1 小时以上：完整读完三篇，并把自己项目的真实情况直接填进模板，让读完之后得到的不是认知，而是一套可执行输入。

## 这套专题最适合哪类项目

- 独立开发项目。
- AI 工具或自动化服务。
- 先能手工交付、后能逐步产品化的项目。
- 有明确社区入口的内容型或工具型业务。

## 典型使用场景

| 你现在的状态 | 最该读的一篇 | 为什么 |
|------|------|------|
| 点子很多，但没有一个在推进 | 方法论篇 | 先确认你是否已经找到值得服务的社区和足够痛的问题，而不是继续收集创意 |
| 有方向，但每周很忙却没有真实进展 | 案例篇 | 你缺的往往不是执行力，而是执行顺序：什么动作该先做，什么动作看起来努力、实际在绕远路 |
| 已经准备今天就开始跑 | 模板篇 | 把 Skill 输入写得更具体，降低“会概念，但不会下指令”的阻力 |

## 这套专题不适合哪类问题

- 融资、税务、法律等专业咨询。
- 已经进入大规模组织化运营的成熟公司问题。
- 纯靠流量套利、没有明确社区与价值交付的项目。

## 常见误区

### 误区一：把它当成“创业鸡汤模板包”

不是。它真正提供的是一套**决策顺序**，而不是几句能让回答更好看的 Prompt。

### 误区二：觉得只要复制模板就能得到正确答案

模板只是输入框架，不会替你补足真实上下文。你必须自己提供社区、约束、目标用户和当前阶段这些关键信息。

### 误区三：只读方法论，不做动作

这套专题的最佳读法不是“读完再说”，而是边读边把自己的项目填进去。否则它会变成另一组让你感觉自己“已经懂了”的收藏夹内容。

## FAQ

### Q1：这套专题适合已经有成熟团队和成熟业务的人吗？

**答：** 不太适合作为主方法。它更适合早期阶段、约束很多、需要先验证问题与交易信号的项目。成熟团队会更关心组织流程、渠道体系和规模化问题。

### Q2：为什么这套专题反复强调手工交付？

**答：** 因为手工交付是最便宜、最直接的验证方式。只有你亲手交付过价值，才更容易知道哪些步骤值得自动化，哪些只是你想象中的复杂系统。

## 现在就该做什么

不需要把三篇都读完再动手。用两个问题定位你的入口，然后读能让你下指令的那一篇：

1. 我说得出“我准备先服务谁”吗？——说不清，先去方法论篇，用 /find-community 把自己放回真实社区里。
2. 我有方向，但今天不知道做什么吗？——是，先对照案例篇的 8 周时间线，看自己卡在哪一周；急着开工就直接复制模板篇的第一个 Prompt。

带着你的真实项目去跑，而不是带着“我读完了”的感觉离开。
