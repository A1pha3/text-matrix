九块九到六百五十九，月费差了七十倍。挑最便宜的买，买错的可能性不低。

四个方案分属不同品类。方舟卖多模型入口，GLM 卖单一模型家族的深度配额，MiniMax 和 MiMo 将代码、多模态和自家模型打包在一起。DeepSeek 是按量 API，WorkBuddy 和 TRAE Work 做的是办公平台，和 Coding Plan 不在同一层。

## 先给结论

| 你的工作方式 | 优先考虑 | 原因 |
| --- | --- | --- |
| 经常在 Doubao、GLM、DeepSeek、Kimi、MiniMax 之间切换 | 方舟 Coding Plan | 一个订阅覆盖多个模型，支持手动切换和 Auto 调度 |
| 已经确认 GLM 是主力模型，代码任务占绝大多数 | GLM Coding Plan | 额度和 MCP 权益都围绕 GLM 编程链路设计 |
| 编程之外还要生成图片、语音、音乐或视频 | MiniMax Token Plan | 文本、代码和媒体生成共用一套额度 |
| 想用 MiMo 模型，并需要全模态、语音或 MiMo Claw | Xiaomi MiMo Token Plan | 四档订阅覆盖 MiMo 模型、主流编程工具与可选 Claw 服务 |
| 用量很低，或要把模型接进线上服务 | DeepSeek API 等按量方案 | 按 Token 付费，低频时不用承担月费，也更符合生产调用方式 |

不确定自己该选哪个的，先别买年费。花一周记下模型调用、峰值时段、长任务数量和多模态用量，数据会告诉你答案。

## 四套方案卖的不是同一种东西

| 方案 | 核心卖点 | 模型范围 | 能力范围 | 计量单位 |
| --- | --- | --- | --- | --- |
| 方舟 Coding Plan | 多模型入口 + Auto 调度 | Doubao / GLM / DeepSeek / Kimi / MiniMax 等 | 纯代码 | 请求数（估算） |
| GLM Coding Plan | 单模型家族深度配额 | GLM-5.2 / GLM-5-Turbo / GLM-4.7 | 代码 + 视觉/搜索/网页/仓库 MCP | prompt 次数 |
| MiniMax Token Plan | 代码与多模态共享额度 | MiniMax M3 / M2.7 + 图像/语音/音乐/视频 | 代码 + 全模态 | Token |
| Xiaomi MiMo Token Plan | MiMo 模型 + Claw 加购 | MiMo V2.5 系列 + 语音 | 代码 + 语音 + 可选 Claw | Credits |

四个方案的区别，从两个维度看就能区分：**模型范围**（单模型家族 ↔ 多模型入口）和**能力范围**（纯代码 ↔ 多模态）。方舟主打多模型，GLM 走单模型深度，MiniMax 和 MiMo 偏向多模态。DeepSeek、WorkBuddy、TRAE Work 连产品类型都不一样，不是 Coding Plan，不该放进同一张表。

定位不同，额度口径不同，价格不能直接除一下算"每元买多少次调用"。

## 比价格之前，先统一五个口径

### 1. 买到的是模型，还是模型入口

方舟一个套餐里装 Doubao、GLM、DeepSeek、Kimi、MiniMax 等好几家模型，不用在多个入口之间来回切。其余三家主要给自家模型，配额、工具和附加能力都绑在一个模型家族上。

常在不同模型之间比输出的人，方舟省了多入口切换的麻烦；团队已经固定用 GLM 的，没必要再为"模型自由"多花钱。

### 2. 额度单位能不能比较

不能直接比。方舟按请求数算，GLM 用 prompt 次数，MiniMax 用 Token，MiMo 用 Credits。同一个 Claude Code 任务可能触发多轮模型调用，长上下文、思考模式、Agent Team 和不同模型的倍率也会改变消耗。

"每 5 小时 1,200 次请求"和"每 5 小时 80 次 prompts"，前者数字大得多，但两者口径不同：方舟统计的是"模型被调了多少次"，GLM 统计的是"用户按了几次回车"——一次 prompt 预计触发 15～20 次模型调用。直接拿两个数字比没有意义。拿自己的典型任务去每套方案里跑一遍，看能完成多少次，比什么都准。

### 3. 月度总量之外，还有短窗口限制

方舟、MiniMax 和 GLM 都公开说明了 5 小时或周窗口；MiMo 则有 Credits、时段倍率和档位差异。并发数与高峰期限流加在一起，实际使用先碰到的是局部限制，而不是页面上最醒目的月度总量。白天同时跑多个 Agent 的用户尤其要看短窗口；偶尔做一次大重构的人更容易被单次长任务和周额度影响。

### 4. 套餐能不能用于生产 API

个人 Coding Plan 面向交互式编程工具，不适用于生产 API 调用。方舟明确说明，套餐额度只在支持的 Coding 工具中生效；GLM 也限定指定工具和产品环境；MiniMax 官方建议生产环境使用按量付费。

要给网站、机器人或 SaaS 后端提供稳定服务，应按 API 的价格、并发、服务条款和可用性重新评估，个人订阅 Key 当生产通道用，迟早要出事。

### 5. 工具兼容不等于体验相同

"支持 Claude Code、Cursor、OpenCode"只说明能接入。模型是否支持图像、思考模式的开启方式、工具调用的稳定性、上下文窗口的计费规则、接口兼容层的完整性，都会影响实际使用。选套餐前，至少用自己的仓库跑一轮需求实现、一轮跨文件重构和一轮失败排查。

| GLM Coding Plan | Lite 49 元/月 | GLM-5.2、GLM-5-Turbo、GLM-4.7 | Lite / Pro / Max；5 小时和周限额；高阶模型按倍率抵扣 | 以 GLM 为主力编码模型的人 |

## 方舟 Coding Plan：多模型入口的账怎么算

方舟提供 Lite 和 Pro 两档。Lite 覆盖 Doubao、GLM、DeepSeek、Kimi、MiniMax 等模型，Pro 用量约为 Lite 的 5 倍。用户可以在 Claude Code、Cursor、Cline、Kilo Code、OpenCode 等工具中使用同一套餐，额度在工具之间共享。

常在不同模型之间比输出的人，或者懒得分别维护多家订阅配置的，方舟省事一些。Auto 模式能减少手动选模型的次数，但如果需要可复现的结果，应固定模型，避免将同一任务交给动态路由。

官方用 Doubao Seed 2.0 Lite、Claude Code 未开启 Agent Team 的场景做过估算：Lite 每 5 小时最多约 1,200 次请求、每周约 9,000 次、每订阅月约 18,000 次；Pro 是其 5 倍。这个数字会随模型、上下文长度和任务复杂度变化，不能当成承诺值。它测的是"在特定模型 + 特定工具模式下，5 小时窗口内能发起多少次模型调用"，换成 GLM-5.2 或开启 Agent Team，数字会立刻往下走。用它推出"方舟比 GLM 多 15 倍额度"不成立——两边的单位不同。

两个边界：套餐额度不能用于普通 API 调用；额度耗尽后不继续扣账户余额，只能等窗口恢复。团队协作和线上服务应改用按量 API。

## MiniMax Token Plan：代码和多模态共用一套额度

MiniMax 同时服务编程与多模态任务。个人开发者可以在 MiniMax Code 里直接使用 Token Plan，也可以通过订阅 Key 接入 Claude Code、Codex CLI、OpenCode、Cursor 等工具。

三档月费分别为 Plus 49 元、Max 119 元、Ultra 469 元。都支持文本、图像、语音和音乐，Max 与 Ultra 额外提供每日视频生成额度；档位越高，可并行运行的 Agent 数量和月度 Token 越多。

限流比价格更需要关注。额度受 5 小时固定窗口和周窗口控制，高峰时段还可能动态调整，未用完的额度不结转。官方也明确把 Token Plan 定位为个人交互式使用，生产环境建议按量付费。

日常工作混着代码、配图和语音的人，共享额度省事。纯编程用户要先算清楚：多模态权益不用时，它们只是套餐介绍里的描述，实际用不上。

- [MiniMax Token Plan](https://platform.minimaxi.com/subscribe/token-plan?code=DRm14bJp5I&source=link)
- [MiniMax Token Plan 快速接入](https://platform.minimaxi.com/docs/token-plan/quickstart)

## GLM Coding Plan：围绕单一模型家族做深

GLM Coding Plan 提供 Lite、Pro、Max 三档，月付原价分别为 49 元、149 元和 469 元；季付、年付及活动价会变化。所有档位目前支持 GLM-5.2、GLM-5-Turbo 和 GLM-4.7，并可接入 Claude Code、OpenClaw、OpenCode、TRAE、CodeBuddy 等工具。

套餐还包含视觉理解、联网搜索、网页读取和开源仓库 MCP。Lite、Pro、Max 每月后三类 MCP 的合计调用上限分别为 100、1,000、4,000 次，视觉理解 MCP 与模型共享 5 小时资源池。

用量按 prompt 估算：Lite 每 5 小时最多约 80 次、每周约 400 次，Pro 和 Max 分别约为 5 倍和 20 倍。一次 prompt 预计触发 15～20 次模型调用，高阶模型在不同时间段还可能按 2 倍或 3 倍抵扣。这里的 80 次 prompt 测的是"用户在 Claude Code 里按下回车的次数"，不是模型调用的次数，更不能直接换算成"能写多少行代码"或"能改多少个文件"。

GLM 在自己仓库里跑顺了，这种套餐比多模型入口更直接。还没确定主力模型就先买高档年费，这笔钱很可能白花。

- [GLM Coding Plan](https://www.bigmodel.cn/glm-coding?ic=QPFQHHZ7CL)
- [GLM Coding Plan 套餐概览](https://docs.bigmodel.cn/cn/coding-plan/overview)

## Xiaomi MiMo Token Plan：从 API 试用入口变成完整订阅

把 MiMo 只写成"10 元体验金"已不准确。当前 Xiaomi MiMo Token Plan 有 Lite、Standard、Pro、Max 四档，月付原价分别为 39 元、99 元、329 元和 659 元，首购与年付另有折扣。套餐覆盖 MiMo V2.5 系列、语音识别和语音合成模型，并支持 Claude Code、OpenCode、Kilo Code、OpenClaw 等工具。

MiMo 使用 Credits 计量，不同模型和时段消耗倍率不同；北京时间 00:00～08:00 按 0.8 倍系数消耗。页面还提供 MiMo Claw 加购项，面向 7×24 小时任务、并行执行和金山办公服务。这部分与普通 Coding Plan 不是同一种权益，购买时应分开核算。

模型迁移有截止日期：官方已公告 V2 系列在 2026 年 6 月陆续转向 V2.5，旧模型名自 6 月 30 日起下线。如果项目依赖固定模型名或接口行为，兼容性测试拖到现在，缓冲期已经过了。

## 一次跨文件重构在四套方案里怎么走

抽象对比看多了，推演一次真实任务。把一个 2,000 行的 `payment_service.py` 拆成 `validator`、`gateway`、`retry` 三个模块，补上对应测试。在 Claude Code 里发起，预计 90 分钟——足够小，能在一轮窗口里跑完；又足够复杂，能触发模型切换、MCP 调用和倍率消耗。

**方舟 Coding Plan。** 任务开始前手动切到 GLM-5.2 做主重构，遇到正则边界条件时切到 Doubao 比较一版替代写法，最后用 DeepSeek 复查测试覆盖。90 分钟里大约发起 6～8 次切换，切换不消耗额外配额，但每次模型调用都计入 5 小时窗口。Lite 的 1,200 次/5 小时在这次任务里够用；如果同时还在跑另一个 Agent 做文档，就要看窗口是否被吃满。Auto 模式在这里不合适——重构需要可复现，模型交给动态路由会让结果难以复盘。

**GLM Coding Plan。** 全程固定 GLM-5.2，不切换模型。90 分钟里大约发起 5～6 次 prompt，每次 prompt 触发 15～20 次模型调用，合计约 100 次调用。Lite 的 80 次 prompt/5 小时够用，但如果开启思考模式或高阶模型倍率，单次 prompt 的消耗会翻倍。视觉理解 MCP 在这次任务里用不上，但仓库 MCP 可以用来快速调出 `payment_service.py` 的历史变更，算额外收益。

**MiniMax Token Plan。** 主重构用 M3，中间需要生成一张支付流程图插进文档。代码和图片共享同一套 Token 额度，不需要切换账户或额外付费。但 5 小时窗口有限：如果上午已经跑过一轮编码，下午的重构可能撞上窗口恢复时间。纯代码任务在这里没有额外优势，多模态额度用不上时，相当于为不需要的能力付了费。

**Xiaomi MiMo Token Plan。** 任务在 00:00～08:00 发起的话，Credits 消耗打 8 折，90 分钟的重构实际计费约 72 分钟。如果任务必须在工作时段跑，就没有这个优惠。MiMo Claw 在这次任务里用不上——它是面向 7×24 小时长任务和并行执行的加购项，单次重构不需要。V2.5 切换后，先确认 Claude Code 配置里的模型名已经更新，否则任务跑到一半可能直接报模型不存在。

四套方案都能完成这次重构，省钱的环节不同：方舟省的是维护多个模型入口的功夫，GLM 配额围绕单一模型算得更准，MiniMax 在代码加配图的混合任务里一份额度两用，MiMo 适合把工作挪到低谷时段的人。

## DeepSeek、WorkBuddy 和 TRAE Work 为什么不放进主表

### DeepSeek：适合按量调用，但不是 Coding Plan

DeepSeek 官方按输入、输出 Token 计费，从账户余额或赠送余额中扣款。它有 Claude Code 等 Agent 集成文档，但没有名为"DeepSeek Coding Plan"的订阅套餐。

低频调用、需要精确核算单次成本，或者要把模型接入生产服务时，按量 API 更合适。代价是 Agent 长任务可能连续发起大量请求，若没有预算上限、缓存和调用监控，账单会比固定订阅更难预测。

- [DeepSeek 模型与 API 定价](https://api-docs.deepseek.com/quick_start/pricing)

### WorkBuddy：交付的是办公结果，不是 Token 配额

WorkBuddy 面向办公任务：方案、PPT、数据分析、软件生成和音视频制作都在一个工作台里完成，并连接腾讯文档、会议、邮箱、微信、企业微信和 ima。购买理由通常是办公任务覆盖和腾讯生态连接，而非模型 API 或 Coding 配额。

一天大半时间在整理材料、做演示和处理协作的人，WorkBuddy 比再买一个编码模型更贴合需求；核心工作是大型代码库持续修改的人，仍应优先比较前面的 Coding Plan。

新用户通过邀请链接注册并登录桌面端，可一次性获得 2,000 积分。积分能跑多少任务取决于任务类型，办公平台的消耗口径和 Coding Plan 完全不同。拿几类日常任务去试，跑完再决定要不要付费。

- [WorkBuddy 邀请注册（新用户 2,000 积分）](https://www.workbuddy.cn/events/invite?inviteCode=1l97lus3od)

### TRAE Work：Agent 平台，和 Coding 配额不在同一层

TRAE Work 是 AI 办公平台：写作、整理、分析、生成这类任务交给 Agent 跑，交付的是结果而不是模型调用次数。Coding Plan 卖编程工具里的模型额度，TRAE Work 把任务本身整个接过去。GLM Coding Plan 的兼容列表里就有 TRAE（前文提过），两边并不冲突，可以搭配着用。

新用户通过分享链接注册并登录桌面端，可一次性获得 5,000 积分。办公平台的积分消耗和任务类型强相关。拿积分跑几个手头的真实任务，跑完就知道要不要续费。

- [TRAE Work 邀请注册（新用户 5,000 积分）](https://www.trae.cn/work-fission/YWBNB8L5RE76)

## 用 7 天数据选套餐

从最低档开始。先用 API 余额、免费额度或月付最低档完成一轮测试——前文各家入口里的新人积分和邀请优惠这时候用正好，零成本换一周真实用量数据，比翻评测文章准确。测试期间每天记下面五项：

1. **真实任务数**：需求实现、重构、测试、排错各完成多少次，不记聊天轮数。
2. **最重的 5 小时窗口**：连续编码时是否触发限额、排队或降速。
3. **模型切换次数**：切换是为了质量，还是因为某个模型经常失败。
4. **非代码用量**：图片、语音、视频、搜索和 MCP 调用到底占多少。
5. **溢出成本**：套餐耗尽后，是等待恢复，还是必须转按量 API 继续工作。

一周后把账算成：

> **有效月成本 = 订阅费 + 溢出调用费 + 闲置权益成本 + 切换与维护成本**

订阅费买高了可惜，买低了溢出成本更贵。闲置权益是用不上的功能在付钱，切换成本是多入口却只用一个模型的浪费。把一周数据填进这四个格子里，哪个环节在漏钱，一算就清楚。

方舟月费不是最低，但省了维护四套入口的功夫。MiniMax 的多模态额度如果每天都用，就不是赠品。GLM 的 MCP 调用若替代了其他搜索和仓库工具，也应计入收益。MiMo 的低谷倍率只对能调整工作时段的人有意义。

## 购买前最后检查一次

- 先月付，再决定季付或年付；至少跑完一次完整迭代周期。
- 用自己的仓库测试，不用官方 Demo 代替真实任务。
- 同时记录短窗口、周窗口和并发限制，别只看"月度总量"。
- 确认套餐是否只允许个人使用、是否限定工具，以及额度耗尽后的行为。
- 检查续费原价、自动续费取消时间、退款规则和邀请优惠期限。
- 线上服务、团队共享或批处理任务，优先评估按量 API，别依赖个人订阅。

## 常见问题

**几个人合买一个套餐行不行？** 不建议。个人 Coding Plan 大多绑定单账户、限定交互式工具，多地同时登录容易触发限流，也违反服务条款；团队使用应选团队版或按量 API。

**邀请积分和首购折扣能叠加吗？** 两者通常属于不同活动：首购价在下单时生效，邀请积分注册后到账，多数情况下互不冲突。各平台规则不一，以下单页和积分到账说明为准。

**要不要等大促再入手？** 月付最低档的试错成本，一般低于等大促省下的差价。可以先月付拿一周用量数据，大促时再用数据决定要不要年付。

**走邀请链接注册，我会吃亏吗？** 不会。邀请奖励是平台额外发的，新人权益一分不少——这也是本文集中放邀请链接的原因：你拿积分，笔者拿一点奖励，比较结论不变。

## 决策框架

方案细节会变，价格会调，模型会迭代，但判断顺序不变：先确定自己要什么——多模型入口、单模型深度、多模态额度、办公平台，还是按量 API；再用一周真实任务测出短窗口和溢出成本；最后才看价格。错过一次折扣无非多等一阵，选错产品类型却会让月费持续打水漂。
