# 过滤规则（x-timeline）

## 一、结构规整（过滤前执行）

| 规则 | 判定与处理 |
| ------ | ------ |
| Thread 合并 | 按 `in_reply_to_status_id` 链式还原：同一作者的连续回复链（每篇回复的 `in_reply_to_status_id` 指向链上前一篇，且作者一致）合并为一个条目；摘要覆盖全串要点，链接指向**串首推**；链上各篇入场时间取最早值参与窗口判定 |
| 重复转推 | 同一原推（同 `post_id`）被多人转推，只保留 1 条；优先保留 `profile.json` 关注层级最高的转推者，层级相同取入场时间最新 |
| 引用对撞 | 原推与其引用推同时在窗口内：保留原推、丢弃引用推；例外——引用推文本含独立增量信息（新数据、新观点、新链接）时两者都保留，引用条目附被引对象链接 |
| 当次重复 | X 可能跨页返回重复条目，按 `post_id` 当次去重（采集脚本已做，处理层复核） |
| 跨日重复 | 命中 `seen-post-ids.json` 指纹库的条目标记丢弃并计数；指纹库滚动保留 90 天 |

## 二、L1 硬过滤（规则判定，零容忍）

| 类型 | 判定信号 |
| ------ | ------ |
| 广告 | `is_promoted`/`promotedMetadata` 标记；"Ad""推广""Promoted" 文案 |
| 时间窗外 | **入场时间**（转推 = 转推动作时间）早于窗口起点；DOM 兜底路径 `entry_time_reliable=false` 的转推入场时间不可得，**不做超窗硬过滤**（采集游标已保证其在窗口内），避免「旧帖新转」误裁 |
| 无法溯源 | 无有效 permalink（`post_id` 或作者缺失） |
| 墓碑条目 | 原帖已删除/账号停用的占位项（GraphQL `TweetTombstone`、DOM 中 "This post is unavailable" 类文案） |

## 三、廉价预筛（保守执行，拿不准一律放行给 LLM）

仅以下两类可不进 LLM 直接丢弃：

1. 纯表情/纯符号文本（无任何字母数字词）；
2. 文本 ≤ 10 字符且无外部链接、无媒体、非核心关注作者。

**禁止**在此阶段做主题/价值判断——那是 L2 的职责。

## 四、L2 LLM 三分类

分批判定（每批约 50 条），每条输出 `keep` / `review` / `drop` 三选一及一句理由。

| 判定 | 标准 |
| ------ | ------ |
| keep（收录） | 命中任一保留信号：技术/产品发布、开源项目、模型更新；行业观点、数据、研究报告、融资消息；`profile.json` 核心关注作者的实质内容；有指向实质文章/仓库/论文的外部链接；**创业常识类（股权/期权/融资/团队管理等对创业者实用的经验与常识，2026-08-19 用户拍板收录）** |
| review（待复核） | 价值拿不准——**宁松勿枉**，进待复核清单，文末单列，禁止静默丢弃 |
| drop（丢弃） | 纯情绪宣泄无信息增量；纯营销引流（加密喊单、带货、抽奖转发）；与 `interest_domains` 完全无关的闲聊；互推/求关注；命中 `muted_keywords` |

### LLM 判定提示词要点

- 输入：推文文本（含转推/引用上下文）、作者层级、外部链接列表、`interest_domains`；
- 输出：严格 JSON，`{"id": ..., "verdict": "keep|review|drop", "reason": "..."}`；
- 约束：只判定信息价值，不评价观点立场；拿不准一律 `review`。
