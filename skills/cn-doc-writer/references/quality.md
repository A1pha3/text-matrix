# 质量评估与规则优先级

> 本文件包含量化评估标准、规则冲突优先级和质量检查清单。由 SKILL.md 按需加载。

---

## 规则冲突优先级

当多条规则同时适用于同一段文本时，按以下优先级处理（高优先级覆盖低优先级）：

| 优先级 | 规则 | 说明 |
|--------|------|------|
| **P0** | 代码块内不检查 | ` ``` ` 或 `~~~` 包裹的区域完全跳过，包括空格、标点、术语 |
| **P1** | 行内代码内不检查 | `` ` `` 包裹的内容不检查中英空格，如 `apiKey` |
| **P2** | LaTeX 公式内不检查 | `$...$` 和 `$$...$$` 视为代码，不检查不翻译 |
| **P3** | YAML frontmatter 不检查 | `---` 包裹的元数据区域跳过 |
| **P4** | URL/路径保持原样 | `https://api.example.com` 内不加空格 |
| **P5** | 术语表 > 通用规则 | 术语表标注 `keep_en: true` 的术语保留英文 |
| **P6** | 中英文空格规则 | 正文中中英文 / 中文数字之间必须加空格 |
| **P7** | 术语首次标注规则 | 每个术语首次出现时标注中文翻译 |
| **P8** | Markdown 换行保留 | 行尾恰好 2 个空格视为 `<br>`，不视为多余空格 |

### 实际冲突示例

| 场景 | 适用规则 | 结果 |
|------|----------|------|
| `const apiKey = "sk-..."` 在代码块内 | P0 | 不检查，保持原样 |
| 正文中写 `apiKey` | P1 | 行内代码内不加空格 |
| `使用 Docker 部署` | P6 | 中英之间有空格 ✓ |
| 首次出现 API | P7 | 写作 `API（应用程序接口）` |
| 术语表中 `Docker` 在 no_translate 列表 | P5 | 不翻译，不标注中文 |

## 量化评估标准

每篇文档按正确性、清晰度、实用性 3 个维度评分，总分 100 分。所有维度都以"对声明的目标读者而言"为前提评估；读者未声明时，先在方案中声明假设读者，再评分。

### 权重分档

权重随文档类型确定，路由判断交付深度时一并选定：

| 文档类型 | 正确性 | 清晰度 | 实用性 | 分档理由 |
|------|------|------|------|----------|
| 教程 / 入门 | 25 | 45 | 30 | 读不懂 = 读者流失，解码成本是主要矛盾 |
| 参考 / API 文档 | 50 | 25 | 25 | 一处错误可能引发读者生产事故，保真优先 |
| README / 快速上手 | 30 | 25 | 45 | 存在意义是让读者跑起来，行为闭环优先 |
| 默认 / 未分类 | 30 | 40 | 30 | 通用技术文档的平衡权重 |

### 评分细则（扣分制）

每个子项从满分扣起，扣到 0 为止；子项满分固定为下表分值，不随权重档缩放。维度得分率 = 维度内子项得分之和 ÷ 子项满分之和；维度得分 = 得分率 × 维度权重。总分先按维度求和，再应用封顶门槛，最后四舍五入取整。这样同一缺陷在高权重档的绝对代价自然放大：一处事实错误，参考/API 档 -5、默认档 -3、教程档 -2.5。扣分必须能在报告中指认到具体位置，指认不出位置的不得扣分。

```text
正确性：
  - 事实正确（10）：每处确凿事实错误 -3（含版本、兼容性、性能结论）
  - 术语一致（10）：每处前后译法不一致 -1；用词漂移只在此扣分
  - 边界与可验证（10）：代码/命令不可运行每处 -5；链接失效每处 -2

清晰度：
  - 结构合理，逻辑连贯（15）：每处结构断裂、层级跳跃或导航缺失 -3
  - 渐进设计与读者适配（15）：每处跳步、未声明的前置知识或密度失控 -2
  - 概念唯一定义（10）：每处定义缺失或歧义 -2；只管定义与歧义，不扣用词漂移

实用性：
  - 可决策可操作（10）：关键操作缺前置条件或验收标准每处 -2
  - 示例真实（10）：示例伪造、与版本不符或不可运行每处 -5
  - 排查与维护（10）：常见问题/错误排查/维护指引整体缺失每项 -5
```

### 可读性量化指标（辅助参考）

- 平均句长：15-35 字/句为宜（>50 字应拆分）
- 段落密度：每段 3-8 行正文（不含代码块）
- 信息密度：每段引入不超过 2 个新概念
- 标题间距：两个同级标题间建议 50-300 字正文
- 代码文本比：教程类建议 30%-50%，参考类可达 60%

> 以上为群体统计参考带，用于发现异常，不是逐句硬规则。禁止为满足指标机械拆分句子、统一句长或压缩段落——指标全达标不等于可读，强行达标会制造新的 AI 味。

### 评分等级

| 等级 | 分数范围 | 含义 |
|------|----------|------|
| S | 90-100 | 专家级，可作为范例 |
| A | 80-89 | 优秀，满足专业标准 |
| B | 70-79 | 良好，有改进空间 |
| C | 60-69 | 及格，需要优化 |
| D | <60 | 不合格，需要重写 |

## 封顶门槛（维度之外的硬约束）

门槛不进维度、不占权重，只在评级时生效。触发任一项：

- 总分不得超过 89 分。
- 不得评为 S 级。
- 必须在报告中显式列出触发的门槛和位置。

### 事实性门槛（正确性）

与"正确性 > 清晰度 > 实用性"的声明优先级对齐。存在 ≥1 处确凿事实错误即触发：代码/命令按文档步骤跑不通、版本或兼容性结论错误、性能结论无出处或与来源矛盾。无法判定的疑点不算触发，标注 unresolved 即可。

### 去 AI 味门槛（可读性门槛）

自然表达不单独评分，而是作为可读性门槛处理。评分时同时看词面、句式和节奏，不只看有没有"本文将"。
完整信号、反例和替换方向见 `references/examples.md` 的「完整信号库」；本节只定义评分约束。

要拿到 A / S，尤其是满分 100，必须同时满足：

- 没有连续元话语、空泛抽象词、口号式判断或机械总结。
- 学习目标、阅读指引、自测问题等结构块确实服务当前内容。
- 列表、小标题和段落节奏不为整齐而牺牲信息密度。
- 去 AI 味后总分不下降，且没有删除事实边界、版本差异、错误条件或 caveat。

辅助判断：删掉抽象词后，段落仍应留下明确对象、动作、限制或结果；否则回到 `references/examples.md` 按完整信号库重写。

### 发布门槛

| 等级 | 发布建议 |
|------|----------|
| S/A（≥80） | ✅ 可直接发布 |
| B（70-79） | ⚠️ 可发布，但建议先修复主要扣分项 |
| C（60-69） | ❌ 不建议发布，需执行 `optimize-cn-doc` 流程优化 |
| D（<60） | ❌ 禁止发布，需重写或使用 `write-cn-doc` 重新生成 |

> **强制规则**：当 AI 生成的文档评分低于 B 级（70 分）时，必须在输出中明确标注警告：
> `⚠️ 本文档评分 XX 分（C/D 级），建议优化后再发布。`

## 质量检查清单

```markdown
### 正确性
- [ ] 技术描述无事实错误
- [ ] 术语使用一致
- [ ] 代码示例完整可运行
- [ ] 所有链接有效
- [ ] 边界清晰，说明了适用范围和限制

### 清晰度
- [ ] 标题层级正确（# > ## > ### > ####，无跳跃）
- [ ] 目录/导航完整
- [ ] 内容逻辑递进合理
- [ ] 对声明的目标读者而言，前置知识假设成立，无未声明的跳步
- [ ] 每个核心概念都解释了"为什么"
- [ ] 概念被唯一定义，无歧义

### 实用性
- [ ] 读者能据此做出决策或执行操作
- [ ] 示例来自真实场景
- [ ] 包含常见问题解答
- [ ] 有错误处理和排查指引
- [ ] 有维护指引、术语表或变更记录

### 封顶门槛（触发即 ≤89，不得评 S）
- [ ] 无确凿事实错误：代码/命令可按文档步骤跑通，版本与性能结论可追溯
- [ ] 无明显模板腔、生成式转场、过度自我声明
- [ ] 无抽象套话密集堆叠、二元口号句、高光总结句
- [ ] 列表没有为了凑结构而机械对称
- [ ] 去 AI 味后总分未下降，事实边界未被删除
```
